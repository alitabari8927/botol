# followings-viewer

یک ابزار وب کوچک و مستقل: یک باکس یوزرنیم اینستاگرام می‌زنی و لیست
حساب‌هایی که آن یوزرنیم فالو کرده (following) را نشان می‌دهد. از همان
سرویس [HikerAPI](https://hikerapi.com) استفاده می‌کند که پروژهٔ insto هم
روی آن ساخته شده — اما این یک پروژهٔ کاملاً جدا است، وابستگی‌ای به insto ندارد.

## اجرای محلی

```sh
python -m venv .venv
source .venv/bin/activate          # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt

export HIKERAPI_TOKEN=hk_live_...  # ویندوز (PowerShell): $env:HIKERAPI_TOKEN="hk_live_..."
python app.py
```

سپس مرورگر را باز کن: <http://127.0.0.1:8000>

## نکات مهم

- **توکن فقط سمت سرور است.** `HIKERAPI_TOKEN` هرگز به مرورگر فرستاده
  نمی‌شود؛ فقط `app.py` (که روی سرور اجرا می‌شود) آن را می‌خواند. هیچ‌وقت
  آن را داخل `index.html` یا کد جاوااسکریپت سمت کلاینت قرار نده.
- سقف پیش‌فرض هر درخواست ۲۰۰ حساب است (قابل تغییر در باکس عدد کنار
  یوزرنیم)، و سقف مطلق سرور ۱۰۰۰ است (`MAX_LIMIT` در `app.py`) تا یک
  اشتباه یا درخواست تکراری، سهمیهٔ HikerAPI‌ات را یک‌جا مصرف نکند.
- اگر اکانت هدف **private** باشد، HikerAPI (بدون لاگین) معمولاً نمی‌تواند
  لیست فالووینگش را بدهد؛ در این حالت پیام خطای مناسب نمایش داده می‌شود.
- این ابزار فقط داده‌های عمومی/در دسترس از طریق API رسمی HikerAPI را
  می‌خواند؛ رعایت شرایط استفادهٔ اینستاگرام و HikerAPI و همچنین حریم
  خصوصی افراد بر عهدهٔ خودت است.

## دیپلوی روی Railway

پروژه از قبل آماده شده (`Procfile` + `railway.toml`، بیلدر `NIXPACKS` که
خودش پایتون و `requirements.txt` را تشخیص می‌دهد — نیازی به Dockerfile نیست).

۱. یک پروژهٔ جدید در Railway بساز:
   - از GitHub: این پوشه را در یک ریپو پوش کن و "Deploy from GitHub repo" را بزن.
   - یا مستقیم از CLI: `railway init` و بعد `railway up` داخل همین پوشه.

۲. در تب **Variables** پروژه، این متغیر را اضافه کن:
   ```
   HIKERAPI_TOKEN=hk_live_...
   ```
   (نیازی به تنظیم `PORT` نیست، Railway خودش آن را ست می‌کند و `$PORT` در
   `Procfile` / `railway.toml` همان را می‌خواند.)

۳. Deploy بزن. بعد از اتمام، از تب **Settings → Networking** یک دامنهٔ
   عمومی (`*.up.railway.app`) بگیر تا صفحه از بیرون در دسترس باشد.

۴. صفحه را باز کن، یوزرنیم را بزن، لیست را ببین.

### نکات دیپلوی
- این یک وب‌سرویس همیشه‌روشن است (نه cron/oneshot)، پس `restartPolicyType = "ON_FAILURE"` یعنی فقط اگر پروسه کرش کند دوباره بالا می‌آید — رفتار عادی و درستی برای این نوع اپ.
- چون فقط یک متغیر محیطی (`HIKERAPI_TOKEN`) لازم دارد و هیچ دیتای ماندگاری روی دیسک نمی‌نویسد، نیازی به Volume نیست.
- اگر خواستی به‌جای دامنهٔ رایگان Railway از دامنهٔ خودت استفاده کنی، از همان تب Networking یک Custom Domain اضافه کن.

## اجرای محلی (جایگزین بالا، برای تست قبل از دیپلوی)

هر پلتفرمی که یک پروسهٔ پایتون طولانی‌مدت را اجرا کند کافی است. فقط:

1. `requirements.txt` را نصب کن.
2. متغیر محیطی `HIKERAPI_TOKEN` را ست کن.
3. دستور اجرا: `python app.py` (یا پشت gunicorn، همون دستور `Procfile`).
